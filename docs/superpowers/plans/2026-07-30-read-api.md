# Read API Implementation Plan (Plan B2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `internal/config` (env parsing plus the aggregating `Validate(subcommand)` that refuses to boot without a secret, parses `TRUSTED_PROXY_CIDRS` as CIDRs and floors `PROOF_RATE_LIMIT_PER_MIN` at 1) and `internal/api` + `internal/ratelimit` (the DTO layer, the four read handlers with golden files, routing, request-id/panic/opaque-error/security-header/write-deadline middleware, the trusted-CIDR client-IP resolver with a bounded key map, scope-disjoint rate limiters, the SSE hub, `/api/health`, `/api/ready`, `/api/ops`, and the two `http.Server`s). Every test in this plan runs against `internal/store/fake` with **no database**, so the whole plan lands on the existing `check` job.

**Architecture:** `internal/config` is the only package in the tree that reads `os.Getenv` (spec §4.1). It is a leaf apart from `internal/fuelmath`, which B2 does not need yet, and it already holds B1's `config.Secret`. `internal/api` programs exclusively against B1's frozen `store.Store` struct of interfaces and `internal/store/fake` — it must never import `internal/store/postgres`, which is what keeps this suite database-free. `internal/ratelimit` is a leaf that takes a parsed `[]netip.Prefix` and knows nothing about HTTP routing, so the client-IP resolver and the bounded counter are unit-testable without a server. Routing is stdlib `http.ServeMux` with Go 1.22 method+path patterns; there is no router dependency and no CORS middleware (spec §6.5).

**Tech Stack:** Go 1.26.5, stdlib only for HTTP (`net/http`, `http.ServeMux`, `http.NewResponseController`, `net/netip`, `log/slog`, `encoding/json`), `github.com/google/uuid` v1.6.0 (already a direct requirement — request ids and record-id parsing), `internal/store` + `internal/store/fake` from B1, golangci-lint v2.12.2. **No new module dependency is added by this plan.** `github.com/go-chi/httprate` is named as an option by spec §6.1 and is deliberately NOT taken: §6.1 also bans `httprate.KeyByRealIP` and `httprate.CanonicalizeIP` by name, the bounded-key requirement is not something httprate offers, and a hand-written fixed-window counter over `map[string]*window` is ~60 lines that this plan can test exhaustively.

### Lint rules — every one of these is load-bearing

- **Zero `//nolint` directives.** `nolintlint` runs with `allow-unused: false` and `require-explanation: true`, so an unnecessary `//nolint` is itself a lint failure. Design around every lint rule instead of suppressing it. There are none in this repository and this plan adds none.
- **`gofmt` is an enabled FORMATTER, not just a linter, and `run.tests: true` means test files count.** Every block in this plan is written gofmt-clean, but a hand-edit can undo that in one keystroke: an aligned `var (...)` block whose longest line changes, or a doc comment containing a space-indented code block (Go 1.19+ gofmt rewrites those to tabs). **Every task's gate therefore begins with `gofmt -w ./internal && test -z "$(gofmt -l ./internal)"`.** Note also that `golangci-lint` truncates at 3 findings per rule by default, so **every gate in this plan passes `--max-same-issues=0`**: without it a fourth identical formatting failure is invisible.
- **Standalone `gofumpt` is not the gate.** Its v0.10.0 binary disagrees with golangci-lint v2.12.2's embedded copy. The gate is `golangci-lint run --max-same-issues=0`. Reformatting to satisfy the standalone binary makes files *inconsistent* with CI.
- **`govet` runs with `shadow` enabled.** Never redeclare a live `err`, including inside a `defer` closure or an `if err := …` that shadows an outer `err`. This is the single easiest rule in the plan to break by reflex, because `if err := f(); err != nil` is idiomatic Go everywhere else. **The mechanical rule: once a function has an `err` that is still read later, every inner error binding is NAMED AFTER ITS OPERATION** — `encodeErr`, `writeErr`, `parseErr`, `flushErr`, `deadlineErr`, `shutdownErr` — or the outer `err` is reused by plain assignment (`err = …`). Every code block in this plan follows that convention; a worker adding an assertion must follow it too. Handlers are the highest-risk site because they typically bind three or four errors in sequence.
- **`gosec` G101 fires on a credential-shaped literal assigned to a named constant or variable, INCLUDING in a test file.** Measured with this repository's exact config: `const probePassword = "p@ss:w/rd?#&secret"` reports `G101: Potential hardcoded credentials`, and `const dsn = "postgres://u:pw@localhost:5432/d?..."` reports `Password in URL`. An inline literal passed straight to a function call does not fire, because the rule inspects assignments and const specs. **This bites B2 harder than B1**, because `internal/config`'s tests must set `SERVER_PRIVATE_KEY` and `POSTGRES_PASSWORD` to plausible values dozens of times. The convention for this plan: build every such value from parts at runtime — `var testPrivKey = "0123456789abcdef" + strings.Repeat("00", 24)` is a binary expression rather than a basic literal — or pass the literal inline to `t.Setenv` without ever naming it. Do not reach for `//nolint`.
- **`gosec` G304 fires on `os.ReadFile` with a non-constant path.** Never read a file at a computed path. Golden files are read by `os.ReadFile(filepath.Join("testdata", name))` where `name` is a **constant per call site**, which is a constant-folded expression at the call and has been verified clean in this repository's `internal/weather` golden tests; if a table-driven golden test needs a computed name, it must go through a helper whose path argument is validated against a compile-time allowlist of golden names declared in the test file. Prefer one explicit call per golden file.
- **`gosec` G404 rejects `math/rand`.** Never import it. This plan needs no randomness: request ids come from `uuid.NewV7()`, and every test fixture value is a literal.
- **`gosec` G112 does NOT flag a missing `ReadHeaderTimeout` on its own. CORRECTED by Task 22; Task 21 measured this twice, independently.** G112 fires only when a server composite literal carries **neither** `ReadHeaderTimeout` **nor** `ReadTimeout`. With `ReadTimeout` still present — which both of Task 21's servers set — deleting `ReadHeaderTimeout` yields a completely GREEN lint run. Both servers set the field, and `TestReadHeaderTimeoutIsSetOnBothServers` is therefore the **only** gate on it, not "belt to the linter's braces". Any task that leaned on G112 for this field was uncovered. A test server built with `httptest.NewServer` is exempt because it is not a composite literal the linter inspects; a hand-built `&http.Server{}` in a test still needs the field, and still will not be told so by the linter.
- **`gosec` G114 flags `http.ListenAndServe` used directly.** Both servers are `&http.Server{...}` values with explicit timeouts and `.ListenAndServe()` on the value, which is the shape that satisfies the rule.
- **`prealloc` runs with `range-loops: true`.** Any slice appended to inside a `range` loop must be created with `make([]T, 0, n)` first. The DTO projection loops (records → items, stations → summaries) are exactly this shape and are the most likely place to trip it.
- **`misspell` runs with `locale: US` and `run.tests: true`, so test files are linted — INCLUDING TEST NAMES.** Write `marshaled`, `serialized`, `behavior`, `normalized`, `canceled`, `honors`, `neighbor`. Never `marshalled`, `behaviour`, `normalise`, `cancelled`, `honours`. The repository's `misspell.ignore-rules` list contains `honour` but NOT `honours`: misspell keys inflections separately, so `Honours` inside a `func TestXHonoursY` name is still a finding and still breaks the mandatory `0 issues` gate. B2 is unusually exposed here because so many test names describe behavior.
- **`exhaustive` runs with `default-signifies-exhaustive: false`.** A `switch` over `store.Status` or `store.ChainStatus` must name all four members; a bare `default` does not satisfy it. The status-projection switch in the DTO layer is the site.
- **`errorlint` is enabled.** Classify errors with `errors.Is` / `errors.As`, never by matching `err.Error()` text. The store-error-to-HTTP-status mapping is `errors.Is(err, store.ErrNotFound)` / `errors.Is(err, store.ErrConflict)` and nothing else.
- **`bodyclose`, `noctx`, `rowserrcheck`, `sqlclosecheck`, `errchkjson`, `musttag`, `nosprintfhostport`, `unparam`, `unconvert`, `recvcheck`, `embeddedstructfieldcheck`, `gosmopolitan` are all enabled.** Three matter especially in B2: `bodyclose` means every `resp.Body` in a test must be closed (an `httptest` response body counts); `errchkjson` means an ignored `json.Encoder.Encode` error is a finding, so every write path handles it; `embeddedstructfieldcheck` means an embedded struct field must be the first field in the struct, which constrains how the weather DTO embeds `weather.WeatherData`.
- **`goconst` fires at 10 occurrences of a repeated 3+-character string.** Header names, content types and the four status literals appear far more than ten times across the api package's tests. Declare them as package-level `const`s in the non-test file and reference those from tests; do not paste `"application/json"` twenty times.

### The store seam and the two prohibitions

- **`internal/api` must NEVER import `internal/store/postgres`, and Task 22 gates it with a test, not a comment.** This is what lets the whole B2 suite run in the ordinary `check` job with no service container. The gate is a Go test that runs `go list -deps` over `./internal/api`, `./internal/ratelimit` and `./internal/config` and fails when any dependency path contains `jackc` or `internal/store/postgres`.
- **`postgres.ErrOperation`, `postgres.ErrTransient` and any wrapped SQLSTATE must never reach a response body.** B2 maps `store.ErrNotFound` → 404, `store.ErrConflict` → 409, and **everything else** to an opaque `{"error":"internal server error","request_id":"…"}`. A `*pgconn.PgError`'s `Error()` is `severity: message (SQLSTATE code)` and the struct carries `Detail`, `Hint`, `ConstraintName`, `ColumnName` and `TableName`, so the default branch never formats the error into the body — it logs it with `slog` at error level with the request id and writes the constant.
- **B1's interfaces are FROZEN and this plan does not change them.** `store.Status`, `store.ChainStatus`, `store.Record`, `store.NewRecord`, `store.Station`, `store.Stats` (with `TotalDataPoints()`), `store.Snapshot`, `store.ListFilter`, `store.StationFilter`, `store.Publication`, `store.BlockHeightUpdate`, `store.RequeueFilter`, `store.Deposit`, `store.ErrNotFound`, `store.ErrConflict`, `store.ErrInvalidText`, `store.ValidText`, the four interfaces, `store.Pinger` and the `store.Store` struct. A signature change here costs rework in both plans.
- **When B2 needs behavior the fake does not yet have, the assertion goes into `storetest.RunStoreConformance` FIRST and both implementations are made to satisfy it.** Adding it to the fake alone reintroduces exactly the class of defect B1's Task 19 exists to close: B2's entire suite runs against the fake, so every fake-versus-SQL divergence is a B2 test that passes while proving nothing. Four such divergences existed in B1's first draft, including a `StationFilter.Search` the fake ignored completely.
- **`config.Secret` is B1's and there is exactly one definition.** Do NOT define a second `Secret` in `internal/config/config.go`, do not alias it, do not add a competing type for the private key. The whole reason it sits in a leaf package is that a hand-copied second copy is how one of them ends up without `MarshalJSON` and serializes a raw credential into a response body.

### The API contract

- **The four status literals are exactly `pending`, `processing`, `completed`, `failed`** — lowercase, no others. They are the values of `store.Status` and the four keys of the frontend's `statusStyles` map. Never `Pending`, never `PENDING`, never an int enum. The `?status=` allowlist is `store.Status.Valid()` and nothing else.
- **The four chain-status literals are exactly `arc-accepted`, `unmined`, `mined`, `aborted`,** and **the SPA never sees any of them.** `chain_status` is projected onto the four wire statuses per spec §13.8 and is never emitted in a DTO.
- **`store.ValidText` failing is a 400, not a 404 and not an empty 200.** `store.ValidText` is the single definition of "bindable text" and B1 already applied it in the store so a NUL id is a MISS and a NUL search matches nothing — which makes the store un-500-able. **B2 applies it in the parse/clamp helpers and returns 400**, because "not found" is the wrong answer to a malformed request and an empty result set hides the mistake from the caller. Both layers on purpose: the store's job is to be total, the API's job is to be truthful. This applies to **every** user-controlled string that reaches a store call — the record id path segment and the `search` query parameter today, and any string parameter added later.
- **No `omitempty` on any field in the spec §13.1 crash list, and Task 5 gates it structurally.** `station.lastTemp` in particular must be **present and explicitly `null`** when unknown: the frontend tests `station.lastTemp !== null`, an omitted key is `undefined`, `undefined !== null` is true, and the UI renders the literal string `"undefined°C"`. Likewise `blockchain` is never `null` and always carries all three keys, and `station.txRecords` is a required non-null number.
- **Timestamps are the `isoMillis` type: UTC, exactly three fractional digits, `Z` suffix — `2006-01-02T15:04:05.000Z`.** Go's default `RFC3339Nano` marshal is variable-width and `timestamp` is compared with `localeCompare` in the SPA, so a fixed shape is required, not merely nice.
- **`totalPages` is `0` when `total` is `0`.** Otherwise the frontend's Next button never disables. The store returns a raw `total`; the derivation is the handler's.
- **`GET /api/weather?` and `GET /api/stations?` with an EMPTY query string are normal requests** — both frontend call sites hardcode the `?` in a template literal. The router must not 400 or 404 on a bare trailing `?`. And Go 1.22 `ServeMux` does not match a trailing slash against an exact pattern, so register **both** `GET /api/weather` and `GET /api/weather/{$}` to the same handler, likewise for `/api/stations`. Do not rely on redirects.
- **Items order is load-bearing: `created_at DESC, id DESC`,** which B1's `List` already provides. The handler must not re-sort and must not reverse.
- **CORS is deleted, not configured.** No CORS middleware, no `CORS_ORIGIN` env var, never `*`, never a reflected `Origin`, and `Access-Control-Allow-Credentials` is never set. Both dev and prod are same-origin by construction.
- **`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY` and `Referrer-Policy: no-referrer` are on every API response** — spec §6.0 control 19. This is a beyond-parity control and it is in the acceptance gate specifically so it cannot quietly not ship.

### Client-IP trust, limiter scopes and the limiter numbers (promoted from B1)

- **Client-IP trust rule.** No forwarding header may be read until the immediate TCP peer is proven to be in `TRUSTED_PROXY_CIDRS`. Untrusted peer ⇒ key on the peer address and consult NO header. Trusted peer ⇒ `CF-Connecting-IP` first, else `X-Forwarded-For` walked from the **RIGHT** taking the first hop NOT in the trusted set, else `r.RemoteAddr`. Always call `.Unmap()` before a `netip.Prefix.Contains` check — `10.0.0.0/8` does NOT contain `::ffff:10.1.2.3` without it. Canonicalize IPv6 keys to a `/64`. **Never use `httprate.KeyByRealIP`** (trusts `X-Forwarded-For[0]` with no peer check) **or `httprate.CanonicalizeIP`** (returns `"::"` for any 4-in-6 address, collapsing every mapped IPv4 client into one bucket). An empty `TRUSTED_PROXY_CIDRS` is legal, means trust nothing, and must emit exactly **one** boot WARN; a malformed entry is a startup error.
- **Rate-limiter scopes must be DISJOINT.** `/api` mounted before `/api/events` means one SSE request decrements BOTH buckets, and `EventSource` auto-reconnects, so the first 429 becomes a retry loop that cannot drain. The SSE limiter is its own sub-router and an `/api/events` request must consume **exactly one** bucket, with a test asserting the general bucket's remaining count is unchanged by an SSE request.
- **`/api/health`, `/api/ready` and `/api/ops` are registered BEFORE the limiter middleware.** A liveness probe that can be rate-limited turns a traffic spike into a pod restart. `/api/ops` is on `OPS_PORT` and therefore structurally exempt, but `/api/health` and `/api/ready` share the routed port and need the explicit ordering.
- **The limiter's numbers are part of the contract, not a tuning detail.** 600 requests/minute general with burst 120 — which, per Task 15's ruling and CORRECTED here by Task 22, means the general scope advertises and enforces **`RateLimit-Limit: 720`, not 600**: burst is permanent capacity, not a start-of-window allowance, so `Decision.Limit` is `limit + burst` and the 721st request in a window is the first 429. The documents now say what the code does; 60/minute on `POST /api/verify`; 30 new SSE streams/minute, which must NOT decrement the general bucket; 12 concurrent streams per IP; a global stream semaphore of 500 answering 503 beyond it; `PROOF_RATE_LIMIT_PER_MIN` default 60 and `>= 1` (zero means unlimited on an unauthenticated outbound proxy); and `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset` plus `Retry-After` on every 429. **The key map is BOUNDED at 10 000 entries with eviction**, because an untrusted peer can otherwise mint keys until the process is out of memory — with a test asserting that N spoofed keys arriving from an untrusted peer produce exactly ONE map entry.
- **B2 builds the `POST /api/verify` and `GET /api/proof/{txid}` LIMITERS but not their handlers.** B3 owns the handlers. Task 16 therefore registers the 60/min verify scope and the `PROOF_RATE_LIMIT_PER_MIN` proof scope against a placeholder handler that returns `501 Not Implemented` with the opaque error body, and asserts the limiter fires on it. That is deliberate: wiring a scope later is exactly how a scope ships unlimited. The placeholder is named in Task 16's deliverable so B3 replaces it rather than adding a second route.

### Test design — non-negotiable, and the reason this plan is shaped the way it is

B1 ran 19 tasks and every one needed a fix round. **Seventeen** of its tests passed while the bug they existed to catch was live, and not one of those was found by reading — every one was found by mutating the code and re-running. The shape was almost always identical: the assertion was fine, but no fixture row could drive the branch it guarded. These rules are how B2 avoids repeating that.

- **For every test that exists to catch a specific defect, this plan NAMES the mutation the test must fail against.** Each task's steps carry a "Mutation check" line. Break the code in a scratch copy **outside the repository**, run the suite, confirm the named test fails, restore. A test whose named mutation does not make it fail is a broken test and must be fixed before the task is committed.
- **Discriminate under the FULL package suite, never under a `-run` filter.** Two of B1's seventeen only discriminated in isolation, because an earlier test in the same file had already changed shared state. `internal/api` is at high risk of this: the SSE hub and the limiter both hold process-level state, so every test that touches either constructs its own instance rather than sharing a package-level one.
- **Fixtures must discriminate.** Concretely, and these are hard requirements on every fixture in this plan:
  - **Distinct values per bucket, never all `1`.** A `Snapshot` fixture gave four buckets the count `1` in B1, and swapping the scan destinations — reporting *pending* as *processing* — passed the whole suite. `/api/ops` consumes `Snapshot` and Task 20's fixture gives all six buckets pairwise-distinct values.
  - **A liveness assertion on anything asserting over a collection.** B1's headline concurrency test passed against a mutation returning **zero rows**, because every assertion held vacuously on an empty result. Every list-handler test asserts a non-zero `len(items)` **before** asserting anything about the items' contents.
  - **At least one row deliberately EXCLUDED from every filter test.** A dropped `id = ANY($1)` went uncaught in B1 because no fixture had a row outside the call. The `?stationId=` and `?status=` tests each seed a row the filter must reject, and assert that row's id is absent from the response.
  - **A positive control on every "nothing errors" table.** An adversarial-input table asserting only "nothing errors" is satisfied by a search matching **nothing at all**. Every adversarial table in this plan carries one input that must match a seeded row.
  - **Never compare a mutated pointer against the variable a seed helper aliased it to.** B1's "does not alias" test passed with the fix removed because the mutation corrupted both sides equally. Where a DTO test asserts that projection does not share a pointer with the store record, it compares against a **separately constructed expected value**, never against the seed variable.
- **Where a rule protects one parameter, test its siblings.** B1's `Offset` was missed entirely because only `Limit` had a rule, and the fake **panicked** on a negative value. In B2 this applies to: `page` and `limit` **and** `stationId` **and** `status` **and** `search` (Task 6 tests all five, not just the two that share a clamp); the record-id path segment **and** the station-id path segment; and every one of the three security headers, not just the first.
- **A gate that cannot be made to fail must be fixed or deleted.** B1's Task 17 shipped twelve gates of which one was **structurally unfailable** for the mutation it named. Eleven real gates beat twelve with one that lies. Every gate in this plan's Task 22 carries its own mutation, and where a static-source-scanning gate is kept because a runtime sibling covers the same property, that is stated at the gate.

### `Snapshot.AbortedCount` is structurally always zero, and `/api/ops` must not pretend otherwise

B1's handover records this as an open design gap, and B2 is the first consumer of `Snapshot`, so it has to be handled here rather than discovered in production.

**The finding, restated:** the frozen `RecordStore` cannot express three transitions the design requires — spending an attempt without terminating the row (so the attempt budget collapses to 1 rather than 3), resetting `attempts`, and **writing `chain_status` `unmined`/`aborted`**. The last one means `Snapshot.AbortedCount` is a bucket that was individually proven wired and that **nothing in the shipped code can increment**. `Snapshot.MinedCount` and `Snapshot.StillUnminedOlderThan1h` are live (`SetBlockHeights` writes `mined`), and the three row-status buckets are live. `AbortedCount` is not.

**What `/api/ops` must do (Task 20):**

1. **Emit the field.** The heartbeat shape in spec §11.1 includes `abortedCount`, the sampler and the ops snapshot share one shape, and dropping a key from a monitored JSON object breaks a dashboard silently. So `abortedCount` is present and is a number.
2. **Emit a sibling that says the field is not live.** The response carries a `"stale"` array of field names whose value is structurally unreachable, and `"abortedCount"` is in it: `{"…":…,"abortedCount":0,"stale":["abortedCount"]}`. An operator reading the JSON, and an alarm author reading it, both see that a zero there means "not implemented", not "no aborts". This is the whole point — a field that can never be non-zero rendered as if it were live is worse than an absent field, because it reads as an affirmative all-clear.
3. **Gate it with a test that fails when the gap CLOSES.** Task 20's `TestOpsStaleListNamesAbortedCount` asserts `stale == ["abortedCount"]` exactly. When Plan C widens `RecordStore` so `chain_status = 'aborted'` becomes writable, that test fails and forces the entry to be removed. A comment would not.
4. **Do NOT change B1's interfaces to fix it.** The widening is Plan C's, tracked in B1's "Known issues carried forward" item 7. B2's job is to stop the gap being invisible.

The other two missing transitions (attempt-spending without termination, `attempts` reset) are not observable through any B2 endpoint and need no B2 treatment.

### The two documented fake-vs-Postgres divergences, and which B2 tests they touch

B1 left exactly two deliberate divergences, both named in doc comments. B2's suite runs only against the fake, so any B2 test sensitive to either is a test that passes locally and proves nothing about production.

| Divergence | B1's note | B2 exposure |
|---|---|---|
| **`PendingDeposits` primary sort key** | Cannot be gated through the black-box `mk(t) store.Store` conformance signature because the fake's clock is frozen, so every seeded deposit shares one `created_at` and the tie order is map-iteration order in the fake. | **None.** No B2 endpoint reads `DepositStore`. `/api/ops` reads `Snapshot` and `Stats` only. **No B2 test may assert on `PendingDeposits` ordering**, and if a future ops field surfaces deposits it must be ordered by `Suffix` in the handler, not relied on from the store. |
| **Station search stemming, multi-word queries and `websearch_to_tsquery` operators** | Postgres's english dictionary matches `runs` against `Running`; the fake does a literal whole-token comparison. Multi-word queries are an implicit AND in Postgres and a single-token equality in the fake. Websearch operators (quoting, `or`, leading `-`) are parsed by Postgres and by nothing in the fake. Prefixes match in **neither**. | **Task 9 is exposed and is constrained accordingly.** `GET /api/stations?search=` tests may assert only: (a) the **numeric shortcut** — a search parsing as an integer is an exact `station_id` lookup, which both implementations do identically; (b) a **single-token exact, case-insensitive** match, which both do; (c) that a search matching nothing yields `200` with `stations: []` and the correct `total`; (d) that an adversarial search (including `?search=0`, the input that 500'd the TypeScript) is a 200 and not a 500. **Forbidden in B2:** any assertion that a stemmed form, a multi-word query, a quoted phrase, a leading-`-` exclusion or a prefix does or does not match. Those are ranking-and-dictionary behavior, they differ between the two implementations by design, and a B2 golden file that pinned one of them would be wrong against production. The handler's own contract — trim, ValidText, numeric shortcut, pass through to `StationStore.List` — is fully testable without them. |

```go
// Len is the count the heartbeat reports as trustedProxyCIDRs.
func (t TrustedProxies) Len() int
```

## Task 4: `isoMillis` and the nullable-pointer projection rule

**Files:**

Produces:
```go
package api

// isoMillisLayout is the ONLY timestamp shape this API emits: UTC, exactly
// three fractional digits, literal Z. Go's default RFC3339Nano marshal is
// variable-width — it trims trailing zeros — and StationRecords.tsx sorts
// timestamps with localeCompare, so a variable-width shape sorts wrong. A
// space-separated form yields Invalid Date in Safari.
const isoMillisLayout = "2006-01-02T15:04:05.000Z"

// isoMillis wraps a time.Time so it marshals in isoMillisLayout. It coerces to
// UTC on marshal: a non-UTC value would emit an offset and break the
// lexicographic sort even at the right width.
type isoMillis time.Time

// MarshalJSON emits a quoted isoMillisLayout string. It never returns an error.
func (t isoMillis) MarshalJSON() ([]byte, error)

// isoPtr projects a *time.Time to a *isoMillis WITHOUT dereferencing a nil.
// It is the whole nullable-pointer rule in one function: a nil in, a nil out,
// and json.Marshal writes literal null. The alternative — dereferencing and
// letting a zero time.Time through — marshals to
// "0001-01-01T00:00:00.000Z", which the frontend's formatDateTime renders as
// 01/01/0001 rather than the em dash it intends for an absent value.
func isoPtr(t *time.Time) *isoMillis

// isoValue projects a non-nullable time.Time. Separate from isoPtr so a
// non-nullable column can never accidentally be given the nullable treatment
// and start emitting null.
func isoValue(t time.Time) isoMillis
```

```go
// TrustChecker is the peer gate's whole dependency. config.TrustedProxies
// satisfies it. A one-method interface rather than an import, so this package
// is a leaf and its tests need no config fixture.
type TrustChecker interface {
	Contains(addr netip.Addr) bool
}

// Resolver turns a request into a rate-limit key.
type Resolver struct {
	Trusted TrustChecker
}

// Key resolves the real client address and returns the bucket key.
//
// STEP 0 (mandatory, and the reason this function is safe at all): is the
// IMMEDIATE peer one of ours? If the host of r.RemoteAddr is NOT inside
// Trusted, return that host's canonical key and consult NO header. Both
// CF-Connecting-IP and X-Forwarded-For are client-settable on any path that
// did not traverse our proxies, so an untrusted peer gets exactly ONE key: its
// own address.
//
// Only when the peer IS trusted, in this order and nothing else:
//  1. CF-Connecting-IP
//  2. X-Forwarded-For, walked from the RIGHT, returning the first hop NOT in
//     Trusted
//  3. r.RemoteAddr
//
// NEVER take X-Forwarded-For[0] blindly: that is both a limiter bypass (a
// fresh key per request) and the memory-DoS vector for the key map. Never use
// httprate.KeyByRealIP or httprate.CanonicalizeIP — the first trusts XFF[0]
// with no peer check, the second returns "::" for any 4-in-6 address and
// collapses every mapped IPv4 client into one bucket.
//
// FAIL CLOSED: a nil Trusted, an empty trust list or an unparseable
// RemoteAddr all key on the peer address, which degrades to one bucket per
// proxy pod — safe, and loud because of config's boot WARN.
func (res Resolver) Key(r *http.Request) string

// canonicalKey renders an address as a bucket key: an IPv4 (including a
// 4-in-6 mapped address, after Unmap) as its own string, and an IPv6 as its
// /64 prefix. The /64 is not cosmetic: a single residential IPv6 allocation is
// commonly a /64 or shorter, so keying on the full 128 bits gives one client
// 2^64 buckets.
func canonicalKey(addr netip.Addr) string

// Limiter is a fixed-window counter over a BOUNDED key map.
//
// The bound is the control, not an optimization: an untrusted peer that can
// influence the key would otherwise mint entries until the process is out of
// memory. At MaxKeys the limiter evicts the least-recently-seen entry rather
// than refusing to track, because refusing to track means allowing.
type Limiter struct { ... }

// New builds a limiter. limit is the requests permitted per window; burst is
// the extra allowance a single client may consume at the start of a window
// (0 for scopes with no burst). maxKeys caps the map; pass DefaultMaxKeys.
func New(limit, burst int, window time.Duration, maxKeys int, now func() time.Time) *Limiter

// DefaultMaxKeys is spec §6.1's bound.
const DefaultMaxKeys = 10_000

// Allow records one hit against key and reports the decision plus the header
// values every 429 and every allowed response carries.
func (l *Limiter) Allow(key string) Decision

// Decision is what the middleware needs to write RateLimit-Limit,
// RateLimit-Remaining, RateLimit-Reset and Retry-After.
type Decision struct {
	OK         bool
	Limit      int
	Remaining  int
	ResetAfter time.Duration
}

// Keys is the current map size. Exported for the bounded-key test and for the
// heartbeat; it is not part of the limiting logic.
func (l *Limiter) Keys() int
```

```go

// Hub fans stats_update payloads out to every connected /api/events client.
//
// It owns the bounded client set and nothing about HTTP. The TypeScript's
// sse.ts:17 is an UNBOUNDED Set and each client pins a Response, a 30 s
// interval timer and a socket, so its 10/min rate limit was the only thing
// between the app and unbounded goroutine and socket growth. The caps here are
// the replacement.
type Hub struct { ... }

// NewHub builds a hub. globalMax is the total concurrent stream cap
// (sseGlobalMax); perIP is the per-client cap (sseConcurrentPerIP).
func NewHub(globalMax, perIP int, log *slog.Logger) *Hub

// errors, not one, because the handler answers 503 for the global cap and 429
// for the per-IP cap: one is our capacity, the other is one client's share.

	ErrHubFull   = errors.New("api: sse global capacity reached")
	ErrPerIPFull = errors.New("api: sse per-client capacity reached")

// The channel is buffered (depth 1) and Broadcast NEVER blocks on it: a slow
// client drops an update rather than stalling the publisher. Dropping is
// correct here — stats_update replaces the whole stats slice wholesale, so the
```

## Open questions a human must decide

These are places the spec is contradictory or silent and the plan made a judgement call rather than inventing a contract. Each names what the plan does today.

1. **`internal/fuelmath` does not exist, so config rules 8, 10, 12 and 13 cannot be evaluated.** The plan makes `Validate` **fail closed** for `serve` and `preflight` with an error naming those four rules, which means a `serve` process cannot boot until the fuel plan lands. The alternative — skipping them with a WARN — is what spec rule 8 exists to prevent. **Decision needed:** confirm fail-closed is acceptable for the interim, or accept that B2 alone cannot produce a runnable `serve`.
2. **Spec §8.15 gives `PROCESSING_LEASE` rule 14 as `> CreateAction_per_call_timeout` (5m > 60s), and B1's known-issue 1 shows that is wrong** — five 60 s double-spend retries within one tick sum to exactly the 5 m default, so the lease can expire mid-attempt and produce the duplicate on-chain write the whole design exists to prevent. B2 implements rule 14 **as written** because changing it is a design decision, and the plan's Task 2 test asserts the as-written predicate. **Decision needed:** restate rule 14 against a whole-leg budget before Plan C passes a lease to the reaper.
3. **Spec §6.1 names `github.com/go-chi/httprate` as the implementation and also bans two of its helpers by name, and the bounded-key requirement is not something it provides.** The plan writes ~60 lines of fixed-window counter instead and adds no dependency. **Decision needed:** confirm the no-new-dependency call, or accept httprate plus a custom key func and a separate bound.
4. **Spec §13.5 says the record id is opaque and the frontend never parses it; spec §6.4's input table says `uuid.Parse` → 400.** These conflict: a strict UUID gate would 400 on any id a future writer chooses, while B1's ids are uuidv7 text today. The plan applies `store.ValidText` and **not** `uuid.Parse`, relying on `ErrNotFound` for an unknown id, and documents the choice at `parseRecordID`. **Decision needed:** confirm, or pin ids as UUIDs forever.
5. **Spec §11.1's heartbeat object and spec §11.2's `/api/ops` are described as the same shape, but B2 owns no wallet, keeper or breaker.** The plan emits only the fields it can populate and asserts the absence of the rest, rather than emitting zeros. **Decision needed:** confirm that a dashboard or alarm consuming `/api/ops` will tolerate the fuel and wallet keys appearing later.
6. **`Snapshot.AbortedCount` is structurally unreachable** (B1 handover item 7). The plan emits it and declares it in a `stale` array. **Decision needed:** whether the `stale` mechanism is the right convention for this project, since it is new here and Plan C will need it again for the other two missing transitions.
7. **Spec §13.3 gives `"lastTemp": 18.3` as an example, which is unachievable** — `air_temperature` is an integer field in the frozen wire schema and `last_temp` is fed from it (B1 known-issue 3). The plan's goldens use integral temperatures. **Decision needed:** either correct the spec's example values, or make `air_temperature` a float field, which is a wire-format version bump.
8. **The stations-search divergence means B2 cannot test the behavior a live search box exercises.** Prefix matching works in **neither** implementation, so search-as-you-type does not work today at all — that is a product question, not a test-coverage one. **Decision needed:** whether typeahead is required, which would need `pg_trgm` or a prefix-aware tsquery and a conformance-suite extension.
